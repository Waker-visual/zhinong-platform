# 证据化 AI 决策闭环

入口为“农场 AI 助手 → 决策闭环”，先围绕单地块墒情核查实现软件闭环。所有演示经营数据均为虚构。本功能不提供灌溉量或药剂剂量，不因模型文字控制设备，也不把完成回执当成田间问题已解决的证明。

## 使用步骤

1. 选择当前农场、地块，填写现场问题，点击“保存证据与建议”。管理员、操作员可保存，查看者只读。系统从认证租户取数，浏览器不能上传或替换传感器证据。
2. 核对“当时的证据”：设备、读数、观测时间、来源、保存时有效性和配置下限。快照同时保留采样间隔、有效期、设备状态和判定原因。当前仅选择该地块最多12个土壤水分测点，不使用其他地块读数。
3. 可点击“请求模型解读”。模型接收问题、虚构证据、关联任务与最近10次复核，工具列表为空。模型解读与规则核验分别标注；未配置或调用失败时回退规则说明，不修改原证据、不自动派工。
4. 管理员点击“确认并安排巡查”，编辑标题、负责人、计划日期和核验要求。确认只创建一条人工巡查任务；相同确认重试返回同一任务。操作员不能自行审批。
5. 在“今日农场”开始并完成任务、填写回执；受阻或取消沿用原流程。回到卡片刷新后可见任务与回执。
6. 管理员点击“记录复测与复核”。系统重新读取本地块测点；也可补录人工土壤水分、观测时间，并在说明中记录测量方法和位置。人工观测必须在任务完成之后、最近30分钟内且不能晚于当前时间；人工来源不会冒充传感器。
7. 系统记录“已取得新观测”或“证据仍不足”。完成前的旧读数不能充当完成后的复测。同一传感器、同一来源且前后均有效时展示数值与百分点变化；人工测点不与传感器测点直接合并。原证据快照不变，各次复核保留历史。
8. 再次请求模型解读，可对照原证据、任务回执和新观测讨论改善迹象、待观察项及资料缺口。旧解读会标注依据较早；请求期间卡片修订变化时拒绝保存过期回答，刷新后重试。

## 判断边界与异常

- 有效读数仅表示当时满足设备在用、来源一致、数值和时效要求，不代表测点具有农艺代表性。设备阈值需按土壤、根层、作物阶段核验；水稻还需水层水位资料。当前没有未来天气预报或灌水量模型。
- 模拟数据只验证软件流程。“已取得新观测”不代表问题已解决或节水增产已验证；“已留存复核”表示记录已保存，资料不足时可继续补测并新增复核。
- 最近展示50张卡、每卡最近10次复核，数据库保留历史。地块迁移到其他农场后不能用旧卡新建任务或复核，应在现农场重新保存依据。
- 所有读取、关联和写入均带认证租户条件；平台账号不能读取。慢模型请求不占用数据库事务，返回后再次校验账号、租户与卡片修订再保存。
- 断网或超时后先刷新核对。相同草稿、确认或复核内容重试复用原请求/关联，不重复创建；修改内容才构成新提交。旧修订返回冲突，避免覆盖他人结果。任务取消后保留历史，不自动再次派工。

## 接口与验证

| 接口 | 用途 |
|---|---|
| `GET /api/ai/decisions?farmId=...` | 当前农场最近50张卡 |
| `POST /api/ai/decisions` | `farmId, plotId, question, requestId` 保存证据 |
| `GET /api/ai/decisions/{id}` | 证据、任务、修订与复核历史 |
| `POST /api/ai/decisions/{id}/explain` | 请求模型辅助解读，有明确规则回退 |
| `POST /api/ai/decisions/{id}/approve` | 管理员确认 `title, assigneeId, dueDate, note, expectedRevision` |
| `POST /api/ai/decisions/{id}/reviews` | 管理员保存 `note, manualValue?, observedAt?, requestId, expectedRevision` |

完整入口为 `scripts/verify.ps1`。回归包含租户与角色、并发与请求幂等、地块归属、旧观测与人工时间限制、快照不变、模型故障及停用期间慢响应。模型替身通过只证明软件契约，真实效果评测见 [AI决策评测指南](AI决策评测指南.md)。

升级新增决策、复核和生产追踪表，兼容原有记录。先停机备份并在副本验证，再构建前后端并重新启动；不要覆盖正在运行的旧 JAR，也不要使用跳过构建选项。旧版程序不认识作废状态，回退时必须使用配套的升级前数据库备份，不能只回退程序包。生产部署、实体设备联调、真实农学效果仍需独立验收。
