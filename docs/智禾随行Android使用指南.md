# 智禾随行 Android 使用指南

智禾随行 1.1 是智禾农场的便携客户端，用同一后端、同一租户账号查看设备和下发受支持的操作。适配 Android 8.0 及以上；Android System WebView 需保持更新（Chromium 107+）。

1.1 统一使用主项目“禾生”标识，连接页和登录页增加田垄、禾苗与设备插画；农场、小田块、农机与灌溉分区提供可搜索的图形选择面板。首页可直接进入灌溉、农机作业和现场画面，正在执行的任务单独显示。分区名称、关联设备与覆盖范围仍来自服务端，不内置演示分区规则。

## 安装与连接

1. 更新并启动主项目。电脑与手机连接同一可信网络；先关闭原来占用 9175 端口的项目进程，再运行：

   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts/start-mobile.ps1
   ```

   此脚本复用 `start-demo.ps1` 的数据库和演示设置，将监听地址改为 `0.0.0.0`，不会另建手机数据库。已完成前后端构建时可加 `-SkipBuild`。使用云数据库启动脚本时，仍使用原有私有配置，只需在启动前设置 `$env:FARM_BIND = '0.0.0.0'`，或通过已有 HTTPS 反向代理提供服务。只运行一个连接该数据库的项目实例。

2. 用电脑的 `ipconfig` 查看当前网络的 IPv4 地址。先在手机浏览器测试 `http://<电脑网络地址>:9175/mobile/index.html`。`127.0.0.1` 在手机上表示手机自身。若不通，检查是否同一网络、访客 Wi-Fi 隔离及 Windows 防火墙；仅在可信的专用网络允许对应 Java 服务/端口。脚本不自动开放防火墙。
3. 将本机生成的 `artifacts/android/zhihe-mobile-1.1.0.apk` 传到手机安装。按系统提示允许当前文件来源安装应用。APK 是本地开发签名的安装包，尚未上架应用商店。沿用已有签名可覆盖升级 1.0，服务器地址保留。
4. 打开 **智禾随行**，填写 `http://<电脑网络地址>:9175` 或自己的 HTTPS 服务器地址。应用检查服务就绪状态及手机页面后进入登录。使用电脑端同一租户代码、账号和密码，无须填数据库或设备密钥。
5. 选择当前农场。也可直接使用手机浏览器打开 `/mobile/index.html`；两者使用相同手机界面。原来的电脑工作台仍在 `/`。

应用只保存服务器地址，登录令牌保留在页面内存中，不保存密码。关闭页面、切换服务器或系统回收应用后需重新登录。退出登录撤销当前会话；修改密码会撤销该账号全部会话。平台账号不能访问经营数据。HTTP 仅用于可信局域网调试，跨网络使用 HTTPS。

## 页面与操作

| 入口 | 功能 | 与电脑端的联动 |
| --- | --- | --- |
| 概览 | 设备数量、上报状态、空气温度、墒情、降雨、虫情和告警 | 读取当前农场已有设备与采样，不把缺测显示成 0 |
| 设备 | 按名称、型号、田块搜索；设备详情、监测指标、24 小时趋势、指令记录 | 台账修改和手机刷新后保持一致 |
| 作业 | 选择田块和具体农机型号，配置幅宽、退让、速度等，预览往复式路线并确认下发；查看进度、暂停/继续/停止 | 使用电脑地图的路线规划与任务持久化接口，农事任务同步产生 |
| 作业 → 分区灌溉 | 选择分区和关联泵，配置模拟时长，启动/停止，查看用水量 | 共享地图灌溉任务和用水记录，估算/实测分开 |
| 实景 | 当前农场的多个摄像头机位、图片或视频及全屏查看；五个初始农场各配置三台 | 复用设备台账中的画面地址与机位，播放器内保留预置画面的简短说明 |
| 账号 | 查看当前身份与服务器、改密、退出 | 与电脑端一致的角色与会话规则 |

手机前台每 30 秒自动读取，回到前台时重新读取，也可手动刷新。切换农场立即清空旧农场设备、详情与画面，延迟返回的数据不能覆盖当前农场。网络失败时标记旧数据并禁用新操作；不创建离线指令队列。

泵闸操作按后端返回能力展示，包含闸门开度、泵启动/停止、频率和急停。只读成员无操作权限；操作员不能设置管理员专用参数或分配普通农事任务，但可以下发模拟农机任务，其关联农事任务始终指派给当前操作员。模拟调度拒绝实体设备。下发前展示农场、设备、动作、参数及模拟/接口属性，需要点击“确认下发”。停用、过期反馈、远程模式和设备故障等最终由后端再次校验。

收到 HTTP 响应、指令被领取、成功回执与设备真实反馈是不同阶段。手机展示服务返回的指令状态和监测时间，不能将“回执成功”当作最新物理状态。响应丢失时保留原请求编号，可“查询操作结果”；没有记录时仅允许人工触发同编号重试，不自动重复下发。农机任务动作也会核对当前状态。

## 田间使用场景

| 场景 | 手机上的操作 | 执行与核对 |
| --- | --- | --- |
| 员工到田边需要补水 | 首页“去灌溉” → 选择覆盖区与关联水泵 → 选择时长 → 确认 | 当前为 10–300 秒模拟限时灌溉；下发后自动进入记录，服务器计时停止，也可人工停止 |
| 员工要安排一次农机作业 | 首页“农机作业” → 选择小田块与型号 → 查看默认参数或展开调整 → 预览路线 → 确认 | 管理员与操作员均可创建模拟任务；记录保留操作者与参数快照，进行中任务优先显示，可暂停、继续或停止 |
| 已接入的现场泵闸需要人工操作 | 设备 → 核对上报时间及当前反馈 → 前往设备控制；水泵可直接点击“停止水泵”进入确认 | 使用既有接口能力；收到指令回执后还需核对最新物理反馈，普通启动指令不等于定时自动停泵 |
| 现场网络断开或切到其他应用 | 显示旧数据和离线提示，禁止新建操作；返回前台重新读取 | 已被服务器接收的任务继续处理；未收到响应时查询原请求编号，不自动重发 |
| 没有打开电脑网页监督 | 员工独立登录手机，在任务记录中查看执行情况 | 无须电脑网页在线，但后端服务必须持续运行并可达。若后端运行在电脑上，关机后手机无法操作；跨网络使用需要部署可访问的 HTTPS 服务 |

手机不会把设备反馈过期、有告警、被停用或已有未结束任务的设备视为可新建作业。农机/灌溉确认页明确列出范围、参数和模拟属性；选择面板可搜索，不更改服务端分区创建、AI 策略或覆盖计算逻辑。

## 数据性质与当前边界

- 仓库所有农场为虚构学术演示；模拟读数、图片和执行状态均明确标注。
- 手机农机规划复用后端按估绘小田块生成的路线。图中呈现相对位置、起终点和计划中心线；不是卫星底图，也不是实时 GPS 轨迹。本版提供自动往复式规划，精细地图编辑与手绘路线留在电脑端。
- 农机和分区限时灌溉目前只支持模拟设备。分区灌溉接口接受 10–300 秒，水量由模拟流量估算，未接入水表时实测值显示“—”。
- 通用 HTTP 泵闸指令沿用现有网关领取/回执能力；需在电脑端完成设备接入及凭据配置。本次没有接入或验收实体设备，也未验证厂家导航、遥控无人机或硬件急停。
- 摄像头沿用图片与原生可播放视频；不内置原始摄像机协议转换、云台操控或推送服务。
- Android 客户端加载后端部署的专用 Vue 手机页面，需联网使用；不是完整离线应用。没有新增独立账号系统、独立数据库、后台推送或 iOS 安装包。
- 本次提供 APK 构建、签名和浏览器模拟手机验收；尚未在实体 Android 手机上安装验收。

## 构建与验证

手机页面与电脑页面统一构建，不新增一套前端依赖：

```powershell
cd frontend
npm ci
npm run build
cd ..
powershell -ExecutionPolicy Bypass -File scripts/verify.ps1
```

`frontend/vite.config.js` 同时输出 `dist/index.html` 和 `dist/mobile/index.html`。后端打包时一起收录；正式部署时须更新整个前端构建产物或重新打包后端。开发时 `npm run dev` 后打开开发服务器的 `/mobile/index.html`，API 仍通过现有代理连接后端。

Windows 上构建 APK：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/setup-android-sdk.ps1
powershell -ExecutionPolicy Bypass -File scripts/build-android.ps1
```

要求 JDK 17+，`JAVA_HOME` 指向实际 JDK，或传 `-JdkPath`。SDK 35 官方包下载到 `.cache/android-sdk` 并校验摘要，也可传 `-SdkPath` 使用已有 SDK。构建使用 Android 官方 aapt2、D8、zipalign 和 apksigner，不依赖全局 Gradle。输出 APK 与 SHA-256 文件到 `artifacts/android/`。

开发签名保存在 `.cache/android-signing/`，该目录和密码均被 Git 忽略。保留该目录才能持续安装同一签名的更新；发布时需单独管理正式签名、递增版本及验证安装升级。构建不嵌入服务器、账号、数据库或模型 API 密钥。

浏览器验收需先构建前端并生成后端 JAR，然后运行：

```powershell
node tools/test_mobile.cjs
```

测试自动启动独立内存数据库和临时账号，不向本地经营库发操作。覆盖五农场隔离、图形选择、摄像头、曲线、两套独立会话的数据互通、丢失响应不重复下发、操作员农机启停、断网禁用、关闭手机页面后定时灌溉自动结束、角色限制、跨租户拒绝及会话过期。截图与结果在 `.cache/mobile-*.png`、`.cache/mobile-browser-result.json`。后端包被正在运行的服务占用时，可以通过 `FARM_MOBILE_TEST_JAR` 指向独立构建的可执行 JAR；测试数据库仍固定为独立内存库。Android 地址校验可通过 `scripts/verify-android.ps1` 单独执行。

## 参考依据与实现

参考 [smart-agriculture-android](https://github.com/Waker-visual/smart-agriculture-android) 提交 `6ac1096636699741297c94bf01f6556c587b1b88`，读取其原生 `app/` 与较新的 `capacitor-app/src/field-app/`。采纳分设备监测、控制、摄像头、农机入口，以及下发前确认、旧数据提示、回执分阶段显示的交互思路。参考项目接口和智禾 DTO 不兼容，未直接使用其 APK 或复制其接口实现。检查版本未找到明确许可证；本次客户端代码与图标由本项目编写，素材沿用智禾已有素材及署名。

Android 容器按 [Android WebView 官方说明](https://developer.android.com/develop/ui/views/layout/webapps/webview) 实现，限定顶层导航为已配置服务器同源，不提供 JavaScript 原生对象桥接，不授予文件、定位、拍照或麦克风权限，保持系统 TLS 校验。签名与校验使用 [Android apksigner](https://developer.android.com/tools/apksigner)。

移动端仅调用已有 `/api/auth/*`、`/api/account/password`、`/api/farm-workspaces`、`/api/assets*`、`/api/alerts`、`/api/farms/{id}/field-map*`。租户由已认证会话推导，不允许手机指定租户 ID 绕过归属检查；操作审计和幂等处理均沿用后端。
