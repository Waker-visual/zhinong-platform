# 智禾农场 0.3.0 使用指南

## 启动与入口

在项目根目录运行：

```powershell
.\scripts\start-demo.ps1 -SkipBuild
```

打开 http://127.0.0.1:9175 。已有用户密码保持原值。首次初始化密码保存在本机 `.cache/demo-password.txt`；修改过的账号应使用自己的新密码。删除密码文件不会重置数据库里的密码。

首次配置独立模拟数据库时运行以下命令，之后 `start-demo.ps1` 会自动启动此实例并读取本地配置：

```powershell
.\scripts\setup-simulation-db.ps1 -MySqlHome 'D:\Softwares\mysql-8.4.9-winx64'
```

默认端口为 3317，仅监听 127.0.0.1，库名为 `zhinong_simulation`。脚本不接管其他 MySQL 服务。数据库、随机凭据和日志位于 `.cache/simulation-mysql` / `.cache/simulation-db.json`，均被 Git 忽略。没有配置时模拟使用 H2，页面如实显示当前引擎；配置 MySQL 后连接失败会阻止服务启动，不会悄悄切换数据库。

## 账号设置

点击左下角头像或昵称进入设置。个人资料支持昵称和本地头像上传，浏览器将头像裁成 256×256 正方形，服务端重新解码并保存 PNG，拒绝外部图片 URL、SVG 和超大尺寸。账号、租户和角色可以查看。

外观可选跟随系统、浅色、深色，以及田园绿、湖泊蓝、麦穗金、玫瑰紫。主题颜色用于左上角品牌标识和当前菜单的指示条；按钮、任务状态和底色保持固定配色，换色后状态含义不变。选择后即时预览，点击保存后归属于当前账号；未保存关闭时恢复原设置。浏览器仅缓存外观偏好，不缓存明文密码。

账号安全要求当前密码和两次新密码。新密码至少 12 个字符且 UTF-8 不超过 72 字节；BCrypt 使用独立随机盐。保存后当前和其他设备会话全部退出。

管理员在设置的“成员管理”中新增、停用成员，或重置本租户操作员、查看者的密码。重置时再次输入管理员当前密码，可生成随机临时密码。旧会话立即失效，成员下次登录必须先修改临时密码。此入口不重置其他管理员或平台账号；管理员自己通过账号安全改密。重置动作进入审计，明文密码不进入审计。

## 农场范围

顶栏的“当前农场”是各页面共用的农场范围：今日农场、运行概览、经营模拟按选中的农场展示；地块管理、种植计划、农事任务、生产记录可以选“全部农场”查看总览；农场概览直接打开选中的农场，选“全部农场”时显示农场列表。选择在页面之间保留；后端按当前租户与农场过滤。种植、任务、产量表展示所属农场。新增业务时可以先选农场，再选其地块，当前筛选会作为默认范围。

## 实景地图

点击农场卡片进入工作台，可切换卫星影像、街道地图和离线平面图，保留图层控制、地块点击、设备详情、边界绘制及点位移动。卫星影像是历史拍摄底图，不是实时航拍或监控视频。

首次默认展示建三江公开农业区域，名称明确标注“示例位置待校准”。管理员点击“位置校准”，填写 WGS84 中心经纬度、东西/南北覆盖米数及位置说明，再保存。原 1000×700 平面坐标映射到这个地理范围；改变校准会同时移动所有地块和设备。校准后须对照影像重新描绘真实边界。范围框外不能落点。该近似映射适用于农场可视化，不是测绘或权属面积测量工具；既有亩数来自地块档案，不能从示例边界推断实际权属。

瓦片来自 Esri World Imagery 或 OpenStreetMap，经已登录的本机接口获取，地图保留供应商署名。卫星主域名失败会尝试同服务备用域名；本机按上游 HTTP 期限缓存已访问瓦片（最多 256 张），到期条件验证，不批量下载。浏览器无需直接访问外部地图域名；本机服务仍需能够访问数据源。网络失败、部分失败、超时都有明确提示与重试按钮，可手动切到离线布局；不会把占位图说成真实影像。街道图在农田区域通常资料稀疏，查看田垄请使用卫星影像。国内其他地图坐标系（GCJ-02 / BD-09）需先转换再填写。生产运营使用在线底图前应核实服务许可与配额。

## 经营模拟操作

1. 进入“经营模拟”，选择有地块的农场。季度默认 2025-06-01 起 90 天、期初生长 40 天；年度固定 2025 全年，每块田一季，按模型播种日开始。
2. 展开地块与作物模型，确认每块田的模型。水稻、玉米、春小麦分别设置周期；无法识别的作物默认“蔬菜通用演练”，需要人工确认。面积、作物和名称取当前档案快照，后续档案修改不影响历史报告。
3. 调整无人机数量/日能力、人工补位日能力、巡检间隔、响应目标、虫害发生日、故障时长、虫害强度、日灌溉能力和施肥完成比例。
4. 点击运行，同一次运行保存三种方案：资源正常、故障期间无人机缺位、同一故障加人工补位。正常和缺位方案的植保只用无人机；补位方案在无人机当日能力不足时启用所填人工能力，包括天气关闭窗口的日期。
5. 比较收获量、虫害归因损失和模拟作业费；点击方案卡片切换日队列、降雨曲线、地块损失分解和事件记录。历史下拉可重新打开结果，下载 JSON 包含全部输入、模型版本、天气 SHA-256 与每日结果。

### 建议验收矩阵

| 试验 | 参数变化 | 观察点 |
|---|---|---|
| 植保缺位 | 缺位 45 天、虫害强度 0.75 | 待防治队列、逾期天数、虫害损失是否增加 |
| 人工接替 | 人工能力从 0 增至 60、120 亩/日 | 损失能否减少，是否仍有超期地块，费用是否增加 |
| 巡检延误 | 巡检间隔从 1 改为 14 天 | 发现日期与损失变化；设备多不代表及时发现 |
| 灌溉不足 | 日能力从 500 降为 0 m³ | 缺水归因，不应算成虫害损失 |
| 无虫害对照 | 强度改为 0 | 无人机缺位不应凭空制造虫害损失 |
| 冬季错配 | 调整开始日或年度虫害日期到未种植时段 | 明确提示虫害未命中在田作物，不能视为验收通过 |
| 权限隔离 | 查看者、另一租户读取运行 ID | 查看者可读本租户；不能创建模拟或读取其他租户 |

### 结果边界与依据

天气为 [Open-Meteo 历史天气 API](https://open-meteo.com/en/docs/historical-weather-api) 的建三江附近 2025 年逐日再分析数据（CC BY 4.0），不是现场设备实测。固定文件保存在 `backend/src/main/resources/simulation`，内含下载 URL、日期、网格位置和出处。运行期间不需要访问天气服务。即使农场地图改到别的地区，当前模拟仍使用这套统一对照天气，页面明确提示。

水分损失参考 [FAO 作物水分与产量关系](https://www.fao.org/4/X5647E/x5647e0e.htm)，只有玉米全季 Ky=1.25、春小麦全季 Ky=1.15 引用其表格。水稻/蔬菜 Ky、Kc、单产、适温、病虫害演变、雨风作业阈值、价格、工费、土壤参数均是公开可见的演练假设，并非当地农学结论。模型没有考虑品种差异、小时天气、土壤类型、药效和抗性等全部因素，不能当成生产预测或施药建议。

灌溉预算按各地块缺口比例分配；防治按地块快照 ID 稳定排队，每日能力用尽就留待次日。产量按缺水、虫害、温度、养分依次扣减并显示 kg 归因，避免百分比重复相加。未成熟地块只显示潜在产量，不计入本期收获；贡献额只扣模拟植保和灌溉费，不等于净利润。模拟不会改写实际农事、生产记录或控制设备。

## 架构与扩展位置

```mermaid
flowchart LR
  UI[Vue 设置 / 农场筛选 / 实景地图 / 经营模拟] --> API[Spring API + 会话及租户权限]
  API --> CORE[H2 核心经营库]
  API --> ENGINE[确定性逐日模拟引擎]
  WEATHER[有来源和指纹的天气文件] --> ENGINE
  CORE -->|地块快照| ENGINE
  ENGINE --> SIM[独立本地 MySQL]
  SIM --> REPORT[输入 / 结果 JSON / 每日资源队列]
  UI --> TILE[Esri / OSM 瓦片]
```

账号独立 `account` 模块；地图校准 `MapConfiguration` 与 `farm_georeference`；模拟分成 `SimulationController / Engine / Store / WeatherData`。模拟库保存 `sim_weather`、`sim_runs`、`sim_run_days`，租户来自服务端会话，不能由请求指定。模拟结果主表保存创建者、模型版本和天气指纹；一轮运行及三方案每日记录在同一 MySQL 事务中写入。核心 H2 和模拟 MySQL 不执行跨库事务，避免把压力测试结果当作真实业务变更。

后续可扩展地区天气数据集、作物校准参数、实际设备作业能力、优先级调度和外协流程。修改模型要提升模型版本并保留旧报告，禁止把旧模拟报告包装成实测结果。

底图署名与许可参考：[Esri 署名说明](https://support.esri.com/en-us/knowledge-base/what-is-the-correct-way-to-cite-an-arcgis-online-basema-000012040)、[Esri 服务条款](https://www.esri.com/en-us/legal/terms/web-site-service)、[OpenStreetMap 瓦片策略](https://operations.osmfoundation.org/policies/tiles/)。
