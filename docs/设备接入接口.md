# 智禾农场设备接入接口

设备类型、独立 WGS84 点位、数据新鲜度和闸门/泵房指令详见 [设备校准与控制验收](设备校准与控制验收.md)。目录接口增加 `presets` 数组，提供各类设备的有效指标模板。每批最多 32 个不同指标，读数可带显式 `unit`。

## 接入步骤

管理员在“设备台账”新增设备，接入方式选择 HTTP 上报，配置监测指标和阈值。保存后进入设备详情，点击“生成接入凭据”。凭据绑定这一个设备和所属租户，只在生成时返回一次；服务端保存 SHA-256 摘要。

向本机服务提交如下报文，`measuredAt` 使用实际采集时刻的 ISO 8601 UTC 时间，不允许未来时间。只上报这台设备已经配置的指标：

```http
POST /api/ingest/telemetry
Content-Type: application/json
X-Device-Key: <在设备详情生成的凭据>

{
  "messageId": "gateway-20260920-0001",
  "measuredAt": "2026-09-19T08:00:00Z",
  "readings": [
    {"metric": "SOIL_MOISTURE", "value": 34.5},
    {"metric": "SOIL_TEMPERATURE", "value": 22.1}
  ]
}
```

PowerShell 请求示例（请替换凭据，不要提交到仓库）：

```powershell
$deviceCredential = '<设备凭据>'
$measurement = @{
    messageId = [guid]::NewGuid().ToString()
    measuredAt = [DateTime]::UtcNow.ToString('o')
    readings = @(@{ metric = 'SOIL_MOISTURE'; value = 34.5 })
} | ConvertTo-Json -Depth 4
Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:9175/api/ingest/telemetry' -Headers @{ 'X-Device-Key' = $deviceCredential } -ContentType 'application/json' -Body $measurement
```

成功响应为 `{"accepted":true,"duplicate":false,"count":2}`。同一设备同一个 `messageId` 的相同报文重试不会重复保存，返回 duplicate=true；报文内容不同则返回 409。请求不需要用户会话，也不能通过 `tenantId`、设备 ID 或租户请求头更换所属主体。设备停用、维护、凭据撤销或所属租户停用时拒绝接收。凭据生成与轮换需要租户管理员会话。

默认服务仅监听本机。远程硬件接入前，需要自行完成受控网络部署、HTTPS、流量限制和运维配置；本版验收使用自动化 HTTP 客户端，没有声称已经完成实体硬件联调。

## 管理 API

除 ingest 外均使用现有登录会话 Bearer 令牌；不接受客户端指定有效租户身份。

| 方法与路径 | 用途 | 写操作角色 |
|---|---|---|
| GET /api/farm-workspaces | 农场卡片、布局预览和统计 | — |
| POST /api/farm-workspaces | 新建农场及资料 | 管理员 |
| GET /api/farms/{id}/workspace | 地块、设备、告警、任务和统计 | — |
| GET /api/farms/{id}/analytics?days=30 | 1–365 天产量及经营统计 | — |
| GET /api/farms/{id}/operations?hours=168 | 运行概览：24–720 小时内 100 个时间片的上报健康度与土壤水分均值、近 28 天地块逐日墒情、作业流水线 | — |
| PUT /api/farms/{id}/profile | 修改农场资料 | 管理员 |
| PUT /api/farms/{id}/layout | 保存地块边界及设备坐标 | 管理员 |
| GET /api/assets/catalog | 指标、单位、量程、类型、协议目录 | — |
| GET /api/assets | 当前租户设备台账 | — |
| POST /api/assets | 新增多指标设备 | 管理员 |
| GET /api/assets/{id} | 详情、最新读数、告警 | — |
| PUT /api/assets/{id} | 修改配置，携带 revision | 管理员 |
| GET /api/assets/{id}/history?metric=SOIL_MOISTURE&hours=24 | 1–720 小时聚合历史及来源统计 | — |
| POST /api/assets/{id}/collect | 模拟设备所有配置指标采集 | 管理员、操作员 |
| POST /api/assets/{id}/readings | 人工录入，measuredAt/readings 结构同上 | 管理员、操作员 |
| POST /api/assets/{id}/credentials | 生成或轮换 HTTP 凭据 | 管理员 |
| GET /api/alerts?farmId=…&status=OPEN | 查询告警 | — |
| PATCH /api/alerts/{id} | status=ACKNOWLEDGED/RESOLVED，note 必填 | 管理员、操作员 |

新增设备示例：

```json
{
  "farmId": "<本租户农场 UUID>",
  "name": "一号土壤站",
  "code": "SOIL-001",
  "deviceType": "SOIL",
  "protocol": "HTTP_PUSH",
  "lifecycle": "ACTIVE",
  "plotId": null,
  "planX": 240,
  "planY": 180,
  "model": "通用多指标采集端",
  "notes": "公共区域",
  "intervalSeconds": 900,
  "revision": 0,
  "channels": [
    {"metric": "SOIL_MOISTURE", "lowerLimit": 20, "upperLimit": 60},
    {"metric": "SOIL_TEMPERATURE", "lowerLimit": 5, "upperLimit": 40}
  ]
}
```

平面图保存格式：

```json
{
  "revision": 0,
  "shapes": [{"plotId": "<地块 UUID>", "boundary": [[100,100],[400,100],[400,300],[100,300]]}],
  "positions": [{"deviceId": "<设备 UUID>", "x": 240, "y": 180}]
}
```

revision 取最新工作台的 farm.layoutRevision。边界至少三个点，最多八十个点；空数组清除边界。X/Y 同时为 null 表示未定位。设备/地块必须属于当前农场；并发版本冲突返回 409。当前 UI 保存当前农场的完整布局。

指标目录包含气象、墒情、水情、虫情、闸门及泵房反馈等，量程、单位以 `/api/assets/catalog` 为准。新增指标需同步服务端 MetricCatalog、模拟基线与验收；新增接入协议需实现接入校验和数据来源，不只增加一个下拉选项。

设备资料可增加 `locationMode`、`latitude`、`longitude`、`controlEnabled`。`locationMode=WGS84` 时经纬度必填，`planX/planY` 必须为 null；`LOCAL_PLAN` 则相反。布局的 `positions` 支持同样的坐标模式，经纬度字段同名，平面字段仍为 `x/y`。已有 WGS84 点位更新时必须明确提交坐标模式，以防旧客户端意外清除安装位置。控制授权默认关闭，仅管理员可修改。
