# 单农场地图与作业指南

入口：农场概览 → 进入农场 → 地图右侧“田块设备 / 农机作业 / 分区灌溉”；也可从“今日农场”的“农场地图”进入。本次沿用 Vue、Leaflet、现有设备台账、设备命令及农事任务接口，新增小田块和地图作业记录。

## 地图与数据来源

- 青禾设备联动演示场的九个小田块依据 2026-10-09 读取的 Esri World Imagery 影像田埂估绘，坐标为 WGS84 `[纬度, 经度]`，不是测量成果。底图采用 Web Mercator 渲染；缩放和平移都重新投影地图坐标，不使用屏幕覆盖图。
- 估绘范围位于原农场配置范围内较清楚的一组小田块。三个原经营地块、登记面积、种植季和历史记录保留；小田块只覆盖其中局部演示区域，估绘面积不能代替经营登记面积，也不能据此认定作物或土地权属。
- 模拟设备安装位置、设备与田块关联、输水管线、阀门与出水口、灌溉覆盖区均为虚构演示。蓝线表示管线，圆点表示节点，蓝色半透明面表示覆盖示意；覆盖面不是水力模型或实际湿润范围。
- 默认细线和低透明填充保留影像纹理；悬停加强轮廓，选择田块以金色描边，任务执行时使用虚线边界。设备使用原创 SVG 图标，状态同时通过文字和角标表达。
- 图层控制分别开关田块、设备、名称、灌溉和路线。卫星底图保留 Esri 等署名；无法连接时明确报告，并可切换离线布局。

首次初始化仅为位置仍为 `47.26,132.73`、地图范围及布局未被用户修改的虚构青禾演示场添加样例；人工调整过的布局不会被覆盖。管理员可进入“编辑平面图”，选择经营地块、填写新小田块名称，点击“新增估绘小田块”，沿底图点击顶点并完成边界。该操作独立保存坐标，保留经营地块；当前支持新增小田块，尚未提供精细边界版本编辑和删除界面。新增田块不会自动虚构灌溉设施。

## 田块与设备联动

选择地图田块或右侧下拉框可查看所属经营地块、作物、估绘面积、当前任务，以及坐标落在田块内的设备与配置给分区的水泵。设备列表与地图点位相互定位、高亮；完整详情沿用监测历史、告警、采集及能力允许的设备控制。

在线/超时/异常状态来自现有设备生命周期、数据时效和告警，运行状态结合新地图任务与新鲜运行指标。模拟协议始终标明模拟；无新鲜反馈不会冒充在线。监测设备提供数据入口，农机提供作业入口，水泵/闸门详情提供其实际支持的指令和回执。

## 五农场演示组合与归档

`scripts/start-demo.ps1` 默认启用 `FARM_DEMO_PORTFOLIO=true`。首次升级保留青禾，并新增新禾水田、丰穗农机、田野稻作、润泽灌溉四个虚构演示场。每个农场具有 9 个小田块、9 个模拟灌溉分区、14 台设备（含 4 类农机）以及关联的两年合成经营历史。四个新区域分别依据 2026-10-10 获取的影像估绘，保存在 `farm-portfolio-estimates.json`；不是把青禾坐标平移复制，获取日期也不是影像拍摄日期。作物、产量、设备位置与设施仍是学术假设。

旧晴川示范园、溪谷设施示范农场、青禾综合示范农场及名称为“验收农场-数字”的旧方案只做归档。默认农场列表和设备总列表隐藏归档项，原有经营记录完整保留。农场档案点击“查看归档”可列出，管理员点击“恢复农场”后重新进入查看历史。迁移只执行一次，不会在下次启动时重新归档已恢复的农场，也不会覆盖后来编辑的布局。普通新建农场不自动生成虚构业务数据。

已有数据库应先备份。云启动脚本也默认启用此演示组合，但本次验收没有向云端迁移数据。直接运行 JAR 时，可显式设置 `FARM_DEMO=true`、`FARM_DEMO_RICH=true`、`FARM_RESEARCH_HISTORY=true`、`FARM_DEMO_PORTFOLIO=true` 后初始化同一组合；关闭组合开关不会删除已经生成的农场。

## 农机作业

1. 选择小田块，进入“农机作业”的“选农机”步骤，查看型号、品牌、马力、设备编号及状态。
2. 点击“下一步：规划路线”。拖拉机按配套机具幅宽规划；植保机按喷洒幅宽规划；收割机按割幅规划；无人机按喷幅/航线间距、边界退让和相对作物高度规划。可选任务类型按机型限制。默认值是演示预设，不是核实过的厂家规格。
3. 选择自动往复式或地图手绘路线。自动推荐沿田块最长边，也可手填角度（东向为 0°，逆时针，90° 为南北行）；可对调起终点。手绘时在地图上点选路径点，支持撤销与清空，服务端检查完整线段及幅宽留边，而非只检查顶点。
4. 点击固定操作区中的“预览规划路线”，查看起終点、箭头、长度、作业范围估算及预计时间。时间按长度÷速度计算；1/10/30/60/120 倍只影响模拟执行的快慢。修改参数后必须重新预览。手绘路线尚未计算重叠覆盖面积，因此显示“未核定”。
5. 管理员点击“确认下发”。按钮不可用时会显示具体原因：未预览、权限不足、设备离线/停用/告警或已有未结束的任务。成功后保存型号、参数、边界和路线快照，显示 `SIM-` 回执编号，创建带 `[模拟农机]` 前缀的关联农事任务。
6. 从任务记录定位田块、设备和路线；暂停、继续、停止及最终结果持久记录，刷新后仍可查看。完成/停止同步农事任务；自动路线的完成面积是规划区域估算，手绘记录的面积 0 表示“未测”，不代表没有作业。

浏览器刷新后保留当前会话所选农场（仍由服务端检查是否可访问）；退出账号会清除选择。正在调度的农机任务不能从普通农事任务进度入口直接取消或覆盖，需通过地图调度操作，避免两个模块出现不同状态。

| 型号 | 类型 / 品牌 | 用户提供马力 | 设备编号 |
|---|---|---|---|
| 柳工1004 | 拖拉机 / 柳工 | 100 马力 | 青禾使用用户提供的编号 |
| 世昌3WPZ-1500F | 植保机 / 世昌 | 50 马力 | 青禾使用用户提供的编号 |
| 洋马1180R | 收割机 / 洋马 | 120 马力 | 待补充 |
| 大疆T100 | 无人飞机 / 大疆 | 未提供 | 待补充 |

用户提供的两个编号仅用于青禾相应设备；其他农场保留空出厂编号，另设唯一 `SIM-农场-序号` 内部编号，不伪造或重复出厂身份。

自动规划支持无内部障碍的凸多边形；沿边内缩至少地头/边界留边及半幅宽加 1 米，作业行及连接段均位于内缩区域。凹形田块可先拆分，也可手绘完全留在田内的路径。过小区域、越界完整线段、过近路径点和过长路线会返回具体错误。当前未接入内部障碍标绘、转弯半径、承载、进出田道路、禁飞区与厂家导航协议，不能作为实机导航指令。GNSS 实际轨迹、现场遥测进度与回执尚未接入，实际轨迹字段为空。实线表示沿计划的模拟进度，虚线表示规划路线。

## 灌溉及用水记录

选择田块后进入分区灌溉，确认对应分区与水泵，设置 10–300 秒模拟灌溉时长，启动后查看状态和停止操作。默认九个分区关联同一模拟泵，因此同一时刻只允许一个作业占用水泵。分区节点是图示，不发送实体分区阀指令。

启动使用现有水泵命令服务，检查设备协议、生命周期、反馈时效、告警与联锁；已有 AI 灌溉占用或地图任务占用时拒绝冲突指令。任务达到时限自动记录模拟停泵命令，重启后依据持久化时间恢复收尾。已有设备详情中的紧急停止仍可使用；地图任务随后据泵状态结束。

记录包括田块、设备、起止时间、状态、操作结果、模拟进度和本次/累计用水。用水单位统一为 m³；估算量按启动时模拟流量（m³/h）× 模拟运行时间积分，不是水表实测。实测水量未接入时显示“未接入”，目标水量未设置时明确显示；当前不支持按目标水量控制。累计值仅包含本农场此模块记录，与设备累计水表指标口径不同。

实体泵/阀可以继续通过原设备详情使用已有能力，但新分区定时灌溉仅支持 SIMULATED 协议。后续需接入网关可靠限时停泵、分区阀开闭回执、水表起止读数及幂等实际作业回执，再开放实体设备执行。

## API、存储及权限

统一前缀 `/api/farms/{farmId}/field-map`：

| 方法与路径 | 内容 |
|---|---|
| GET `/` | 小田块、管网分区、最近 100 条任务及全部记录累计用水 |
| POST `/parcels` | 管理员新增 WGS84 估绘边界，限制在当前配置范围内 |
| POST `/routes/preview` | 根据田块和参数计算规划线 |
| POST `/jobs` | 管理员下发模拟农机任务，requestId 保证重试幂等 |
| POST `/irrigation` | 管理员/操作员启动模拟定时灌溉 |
| POST `/jobs/{id}/actions` | 暂停、继续、停止；灌溉只支持停止 |

存储包括 `farm_map_parcels`、`farm_map_zones`、`farm_map_jobs`、`farm_archives`、`demo_portfolio_farms`、`machinery_profiles`、`machinery_job_plans` 与 `farm_map_job_events`；H2 与 MySQL DDL 同步维护，只新增表，不改写旧任务结构。新农机执行时钟和快照由 `machinery_job_plans` 保存，旧任务兼容读取。归档列表为 `GET /api/farm-workspaces?archived=true`；恢复为管理员 `POST /api/farms/{id}/restore`。资产接口的 `machinery` 字段提供型号档案。

按仓库启动方式重新构建并启动即可创建新表。连接已有数据库前按项目指南备份；不清空历史、不上传本地数据库。身份、租户及角色从认证会话获取，不接受请求体指定租户，平台账号不能读取经营数据。读写、关联和模拟定时处理都包含租户范围。

本地启动：在项目根目录运行 `powershell -ExecutionPolicy Bypass -File scripts/start-demo.ps1`，默认地址 `http://127.0.0.1:9175/`。云数据库启动继续使用现有 `scripts/start-cloud.ps1` 与本机私有配置，地图功能不需要额外 API 密钥。

验证命令：`scripts/verify.ps1`；准备了本机独立 MySQL 环境时使用 `scripts/verify-mysql.ps1`。新增测试覆盖坐标保留、地头内缩、边界内路线、无效/凹形拒绝、任务状态、幂等、灌溉冲突、估算与实测区分及跨租户拒绝。

浏览器验收：构建前后端后运行 `node tools/test_farm_portfolio.cjs`。它使用随机临时端口、随机口令和独立内存数据库，不向正在运行的农场下发操作；验收截图和结果保存到 Git 忽略的 `.cache/portfolio-*`。检查卫星加载、缩放拖移、双向选择、机型信息、手绘/撤销、自动路线、模拟下发、暂停/继续/停止、刷新后的记录及灌溉估算水量。

2026-10-10 五农场版本验证：`scripts/verify.ps1` 通过 106 项实际执行的后端测试（10 项 MySQL 条件测试在该轮跳过）、前端构建、9 项项目检查测试、3 项地图坐标测试与公开范围扫描；独立本机 MySQL 再执行 10 项接口与数据测试，全部通过。五个农场均在 Edge 验证了卫星地图、9 块田、9 个灌溉分区、4 类机型和路线预览；青禾完成了手绘/撤销、下发、暂停/继续/停止、刷新恢复及定时灌溉验证。390px 视口无横向溢出，无页面脚本异常。前端保留原有包体积提示。

## 参考设计

检查参考仓库 `zzzzzmeng/smart-agriculture-system` 提交 `1cb92346f144a5fe6885bc9c0e0397499ddcbd22`。其农场总览/地图组件提供小田块描边、悬停、选中、类型设备符号和泵闸关联展示；智能物联屏以水情、泵闸操作与日志为主，共享地图模块另有路线播放能力。复用的是这些交互思路，没有声称参考仓库具备完整实机导航或实时轨迹系统。

进一步检查 `machinery/CloudDispatch.vue`、`OperationTrace.vue`、`machineryOperationData.ts` 和服务端 `smartTractorController.java`。适合借鉴的是机型卡片、三步调度、预设/手绘路线和地图播放。该版本 `CloudDispatch.vue` 的部署确认主要是前端成功弹框及界面重置，不能据此认定已经发送真实导航任务；本项目补上了后端持久化、能力检查、幂等、互斥和模拟回执。现有厂商历史任务查询与回调也不等同于实时导航下发。

本项目重新编写实现与 SVG 图标，未复制参考代码、素材或账号信息。参考树未找到明确 LICENSE，因此不导入其源码。沿用当前 Leaflet 与 Esri WGS84 底图，不搬入参考项目的高德坐标转换和大屏装饰。
