# 单农场场景与验收指南

本轮围绕家庭农场的日常操作优化，不改变平台管理员和租户之间的数据边界。

## 场景：112 亩家庭农场的一季度

禾间家庭农场为虚构验收租户：东区水稻 60 亩、西区玉米 40 亩、近棚蔬菜 12 亩。农场主负责安排，两名操作员分工执行，查看者跟踪结果。模拟墒情点不连接实体设备。

日常演练使用验收当天日期，以便观察今日与逾期待办。季度计算单独回放 2025-06-01 起 90 天天气，期初生长 40 天；历史模拟不会改变日常任务、实际产量或设备状态。

| 检查情景 | 暴露出的原问题 | 本轮实现 |
|---|---|---|
| 一人管理一座农场 | 登录后仍需在管理总览中寻找工作入口 | 默认今日农场；单农场自动选中；跨收获、种植、地图和模拟保留上下文 |
| 巡田发现虫害 | 操作员只能改状态，无法提交现场问题 | 地块关联的问题上报、优先级、上报人和时间 |
| 无人机检修 | 任务看似在执行，实际资源缺口没有记录 | 受阻原因、优先展示、负责人和人工/无人机/外包方式调整 |
| 两名操作员协作 | 无负责人，容易误操作其他人的任务 | 默认我的队列；服务端校验负责人；旧状态入口不能绕过新流程 |
| 完成防治 | 点击完成无法证明实际作业 | 实际方式、面积、结果、操作者和时间；已结束任务不能重复提交 |
| 处理后复查 | 完成任务不代表虫害消失 | 农场主填写复核依据后关闭现场问题 |
| 田间手机操作 | 图标导航和宽表不利于现场使用 | 文字导航、卡片队列、原生模态表单、触控按钮和单列布局 |
| 收获录错或重复提交 | 无法规范更正，网络重试可能重复累计 | 请求幂等、批次和收获任务关联、修订号校验、理由与历史快照；作废记录保留且不累计 |

## 收获台账与批次追溯

管理员和操作员可以登记收获。选择种植批次时，批次必须属于当前地块，收获日期须在该批次起止日期内。可进一步关联同地块、已完成的收获任务，任务日期也须位于批次周期内；关联任务时必须同时选择批次。未关联的历史台账继续有效，旧客户端仍可以按地块、日期、产量和备注登记。登记重量最多两位小数，界面不应以四舍五入方式悄悄改变用户输入。

只有管理员可以更正或作废，必须填写理由。每次变更均保留操作者、时间、修订号和台账快照；第一次修改旧记录时，会先保留旧值快照。两个管理员同时修改同一条记录时，后提交者须刷新后核对，不能覆盖已保存的变更。已作废记录不能再次更正或作废，可按实际情况另建正确记录。

作废不等于删除：台账与变更历史仍可查询，经营总览、农场产量趋势、分地块统计、经营中心及 AI 的收获统计不再累计该记录。更正后按新日期和新重量统计。研究演示的收获关联完整性检查只检查未被用户修改的合成记录，正常新增和作废不会被误判为演示数据损坏。

客户端登记时应生成一次提交标识，并在结果未知、超时或断网重试时复用。同一租户、相同标识和相同内容只产生一条记录；同标识但内容不同返回冲突。修改草稿或确认新建另一条记录时才换新标识。旧客户端未传提交标识时无法获得请求重试保护。

接口保留原有大写台账字段，并增加 `PLANTING_ID`、`TASK_ID`、`STATUS`（`ACTIVE` / `VOID`）、`REVISION`（首次为 0）和 `CHANGE_REASON`。`POST /api/production` 新增可选 `plantingId`、`taskId`、`requestId`；`PUT /api/production/{id}` 接收完整台账字段、关联、`reason` 和 `expectedRevision`；`POST /api/production/{id}/void` 接收 `reason` 和 `expectedRevision`；`GET /api/production/{id}/history` 按修订顺序返回 `REVISION`、`ACTION`、`REASON`、`ACTOR`、`OCCURRED_AT` 与 `snapshot`。平台账号不能读取上述经营数据，所有关联和变更均按登录租户校验。

结构为增量新增 `production_tracking` 与 `production_history`，沿用旧 `production` 记录并兼容已有 `production_lineage` 合成数据关联。H2 随项目初始化补建；MySQL 新库结构由 `node tools/generate_mysql_schema.cjs` 生成。已有 MySQL 库应先备份、审查并执行两张新增表的 DDL；不清空或重建旧台账。

验收时先登记一笔虚构收获，重复提交同一标识，确认列表仅增加一条。管理员更正重量，查看历史中的原值与新值；用旧修订号再次提交应提示刷新。作废后核对台账仍保留、总览和农场产量统计已经扣除。操作员更正或作废、邻场管理员查询历史、平台账号读取台账均应被拒绝。

## 季度模拟结果

三组模型对照共享 112 亩地块，3 天响应目标，虫害在第 20 天发生，无人机缺位 45 天，人工能力 30 亩/日。正常巡检间隔 3 天，灌溉能力 500 m³/日。数据来源与假设可在经营模拟底部展开查看。

| 输入变化 | 资源正常收获 kg | 无人机缺位收获 kg | 人工补位收获 kg |
|---|---:|---:|---:|
| 无人机缺位对照 | 77,556.48 | 50,513.85 | 76,735.06 |
| 巡检间隔改为 14 天 | 70,766.39 | 50,513.85 | 70,542.26 |
| 灌溉能力降到 30 m³/日 | 62,010.32 | 40,837.54 | 61,415.70 |

这些是确定性流程模型输出，不是实地产量预测。水稻、玉米、蔬菜具有不同模型周期、水分和温度响应；通用蔬菜参数没有品种标定。以第一组为例，无人机缺位时队列超期 41 天，人工补位后为 0 天；但作业成本从 5,852.25 增加到 7,516.25 元。巡检太慢时，即使补齐作业资源也不能消除前期损失；缺水时单纯增加植保资源也不能恢复产量。因此界面保留“上报、资源缺口、回执、复核”四类信息，模拟参数仍由使用者明确确认。

## 验收账号

本机运行 `node tools/prepare_farm_acceptance.cjs` 创建独立验收数据。需要先启动服务，并能使用平台账号登录。首次演示密码默认从 `.cache/demo-password.txt` 读取；若平台账号已经改密，可在当前终端提供 `FARM_PLATFORM_PASSWORD`。脚本不会覆盖已有密码或清空旧租户。

| 身份 | 租户代码 | 登录账号 | 应检查的行为 |
|---|---|---|---|
| 农场主 | family-trial | admin | 安排、调整、取消任务；复核问题；维护成员 |
| 田间操作员 | family-trial | worker | 我的任务、上报、受阻、完成回执 |
| 协作操作员 | family-trial | backup | 可查看农场情况，不能执行已分配给 worker 的任务 |
| 查看者 | family-trial | viewer | 查看问题、历史和模拟报告，没有业务写入按钮 |
| 邻场管理员 | neighbor-trial | admin | 不应看到 family-trial 的记录 |
| 平台管理员 | platform | platform | 管理租户；不能访问租户经营数据 |

每个新账号使用独立随机密码，保存在本机 `.cache/farm-acceptance-accounts.md`，不发布到 GitHub。平台账号沿用原密码。重跑脚本保留现有任务状态和密码；用户改密后，旧密码文件不会自动更新。

## 按顺序验收

1. 农场主登录：确认默认今日农场，查看东区未安排虫害和西区受阻任务。选择东区问题“安排处理”，指派 worker 并确定日期。
2. worker 登录：默认只显示自己负责与未分配的任务；选择“报告受阻”，说明无人机缺位。
3. backup 登录：取消“只看我负责”可看到全场任务，但对 worker 的任务没有开始、受阻、完成按钮。
4. 农场主在任务卡的“更多”菜单中选择“调整安排”，改为人工或外包，写明人员和能力。受阻提示继续保留，直到实际进展被报告。
5. worker 提交完成回执：必须选择已确认方式，填写大于零且不超过地块面积的作业面积，以及结果说明。
6. 农场主复核现场效果，填写依据后关闭问题。取消未完成任务时问题回到待安排，可重新派发。
7. viewer 查看已结束任务的记录；检查执行人、方式、面积、时间和备注完整。
8. 在手机窄屏下上报问题，打开记录收获，确认当前农场自动保留。通过地图按钮打开同一农场。
9. 打开经营模拟历史中的三个“家庭农场季度验收”报告。选择不同方案和地块查看差异、每日队列、天气和归因结果。

## 交互参考与边界

- [Farmbrite：任务管理](https://help.farmbrite.com/help/tasks-tasks)：参考首页待办、负责人、未分配任务、不同任务视图的组织方式。
- [Farmbrite：移动端工作](https://help.farmbrite.com/help/accessing-farmbrite-on-mobile)：参考现场记录产量与跟进任务的短操作路径。
- [AGRIVI：Field Operations](https://www2.agrivi.com/blog/agrivi-presents-field-operations-new-way-seamlessly-manage-your-farm-operations)：参考围绕地块集中任务、作物和地图信息的方式。

视觉采用中性底色与墨色主按钮，颜色只用于两处：任务和设备状态（执行中为蓝、完成为绿、受阻为橙、逾期为红；既逾期又受阻时按逾期显示）以及品牌标识。深浅两套主题共用同一组语义令牌，不复制第三方产品素材。

本轮实现负责人执行限制，不等同于同一租户内的地块级保密权限：同租户成员可查看本租户经营数据。没有无人机调度硬件、消息推送、离线同步或真实农药处方。模拟不会自动派发真实任务。第三方天气、地图和模型假设继续明确标注来源。
