# 农场 AI Agent 界面设计规格

## 目标

把农场 AI 助手从“等待一次完整回答的聊天框”升级成可观察、可恢复、可审阅的 Agent 工作界面。用户能看见回答正在发生什么、哪些数据动作已经完成、哪些动作需要人工确认，同时可以继续阅读历史内容，不被流式输出抢走滚动位置。

第一阶段覆盖当前 AI 助手的农事对话主链，并为天气与四情、灌溉管理保留一致的状态和视觉语言。所有业务数据继续来自当前租户和当前农场；规则回退和同步接口继续可用。

## 当前基线

- 前端为 Vue 3.5 + Vite，AI 页面实现于 `frontend/src/ai/FarmAssistant.vue` 和 `frontend/src/ai/assistant.css`。
- 对话发送通过同步 `POST /api/ai/conversations/{id}/messages` 完成，前端在请求期间只显示一行静态的“正在读取”提示，完成后重新读取整段历史。
- `AssistantText.vue` 只支持加粗文本，没有消息分段、来源、工具结果或 Markdown 渲染。
- 后端 `AiConversations` 持有一次同步模型调用；`LlmGateway` 当前使用 OpenAI 兼容的非流式 `/chat/completions`。旧 `/api/ai/ask` 有工具调用循环，但尚未接入对话页。
- 项目已有全局 `.skeleton`、扫光动画和 `prefers-reduced-motion` 规则，应复用这些基础能力，不引入 React/Tailwind UI 运行时。

## 设计方向

### Agent 状态可见，但不暴露不可审计的内部思维

折叠区只展示用户可验证的活动摘要：读取哪些资料、调用哪个工具、返回了多少条结果、正在等待什么确认。模型内部的逐 token 思维不进入持久化记录，也不作为“真实推理”展示。

活动摘要在运行时自动展开，完成后默认折叠；用户可以手动展开已完成的活动。工具名称、状态、耗时、结果摘要和来源数量都使用短句表达，避免把技术字段直接暴露给农场用户。

### 视觉语言

- 基础色沿用现有农场主题：`--surface`、`--subtle-bg`、`--brand`、`--label-fg`、`--danger`，不新增一套 AI 专属颜色。
- AI 的记忆点是“田间作业条带”：左侧细状态线连接活动步骤，活动行使用浅底、短标题和状态点；正文保持当前克制的阅读宽度。
- 流式文本使用轻量光标和状态扫光；活动完成使用勾选或状态点，不使用连续弹跳和大面积渐变。
- 移动端将历史对话变成可横向滚动的紧凑栏，活动详情和来源卡片保持全宽。

### 消息与活动模型

前端统一消费以下运行模型：

```ts
type AgentRunStatus = "submitted" | "running" | "completed" | "error" | "cancelled";
type ActivityStatus = "pending" | "running" | "completed" | "error";
type ActivityKind = "context" | "tool" | "source" | "approval" | "task";

type AgentActivity = {
  id: string;
  kind: ActivityKind;
  label: string;
  status: ActivityStatus;
  detail?: string;
  resultSummary?: string;
  startedAt?: string;
  finishedAt?: string;
};

type AgentRunEvent = {
  sequence: number;
  type:
    | "run.started"
    | "activity.started"
    | "activity.updated"
    | "activity.completed"
    | "message.delta"
    | "message.completed"
    | "run.completed"
    | "run.error";
  activity?: AgentActivity;
  delta?: string;
  messageId?: string;
  diagnostic?: string;
  error?: string;
};
```

活动摘要允许断线后恢复，但只保存已完成的安全摘要，不保存模型原始请求、凭据、完整工具参数或不可验证的内部思维。

## 前端结构

### 组件边界

- `AiConversationView`：运行状态、消息列表、滚动锚定和重试入口。
- `AiMessage`：用户/助手消息布局、正文、操作按钮。
- `AiActivityDisclosure`：折叠式活动摘要，负责自动展开/收起和键盘交互。
- `AiActivityRow`：单个工具、来源、任务或审批状态。
- `AiStreamingStatus`：提交、读取、生成、完成和错误状态。
- `AiComposer`：输入、发送、停止、重试和字数提示。

第一阶段可以先在 `FarmAssistant.vue` 内组合这些小组件；当消息协议稳定后再拆分文件，避免先做无收益的重构。

### 滚动规则

1. 用户发送新问题时，把用户消息和活动占位插入底部。
2. 仅当滚动容器距离底部不超过 72px 时自动跟随流式内容。
3. 用户向上滚动后暂停跟随，显示“回到最新”按钮并保留阅读位置。
4. 活动完成或错误时不强制滚动；点击回到底部才恢复跟随。
5. 切换历史对话时定位到末尾，但不使用平滑动画抢占焦点。

### 加载、错误和空状态

- 首次加载：历史栏、消息区域、分析页和灌溉页分别显示与最终布局等高的骨架屏。
- 发送中：显示活动条带和助手消息骨架，不清空已有消息。
- 流式失败：保留已生成正文和活动摘要，展示“重试本次回答”；重试沿用 `requestId` 保护幂等。
- 模型不可用：明确显示规则回退，不伪装成流式模型回答。
- 空对话：保留当前快捷问题，但加上“会先读取当前农场资料”的说明。

## 后端接口与持久化

### 流式接口

新增 `POST /api/ai/conversations/{id}/stream`，请求体沿用现有 `Question`：`question`、`requestId`。响应使用 `text/event-stream`，每个事件携带上述 `AgentRunEvent` JSON。

- 会话、农场和租户权限在开始流式响应前完成校验。
- `requestId` 先查已有运行结果；重复请求不得重复写入用户或助手消息。
- 上游模型使用 OpenAI 兼容 SSE；工具调用和文本增量统一转换为安全的 Agent 事件。
- 客户端断开时停止上游读取，释放并发信号量，不写入半截的 assistant 成功消息。
- 旧同步接口继续保留，作为不支持流式、超时或服务降级时的回退路径。

### 运行摘要存储

新增租户隔离的 `ai_message_activities` 表，保存 `tenant_id`、`conversation_id`、`message_id`、`activity_id`、`kind`、`label`、`status`、`detail`、`result_summary`、开始/结束时间和顺序号。敏感参数只保存脱敏摘要，保留租户复合键和外键约束。

读取对话消息时返回 `activities` 数组；旧消息没有活动时返回空数组，兼容已有数据库。

## 分阶段交付

### 阶段 A：前端状态骨架

先实现事件 reducer、活动折叠、骨架屏、滚动锚定和错误重试，并提供本地同步适配器，让现有同步接口也能驱动同一套 UI。此阶段可独立验收视觉和交互。

### 阶段 B：真实流式链路

实现 SSE 解析、`LlmGateway` 上游流式读取、后端事件转译、运行取消和活动摘要持久化；前端切换到真实流式适配器，保留同步回退。

### 阶段 C：Agent 操作卡片

把现有灌溉建议接入审批活动，增加来源、任务完成进度、重试和复制操作；不增加未经现有业务接口保护的设备写入路径。

### 阶段 D：质量收口

补充租户隔离、幂等、事件顺序、断线、超时和回退测试；用本地预览验收桌面、移动、浅色、深色和 reduced motion。

## 验收标准

- 首次进入 AI 助手时，页面结构不会因数据返回而跳动。
- 用户发送后能看到状态活动、助手正文增量和完成态，不必等待整段历史重新加载。
- 用户阅读旧消息时，流式输出不会把滚动位置拉回底部。
- 活动摘要运行中自动展开，完成后自动收起；键盘和屏幕阅读器可访问。
- 失败时保留可见上下文，可重试且不重复写入。
- 规则回退、旧同步接口、租户条件、会话幂等和敏感信息扫描继续通过现有检查。
- `prefers-reduced-motion` 下不运行扫光、光标和展开动画，但信息层级不改变。


## 阶段 E：活动时间线与消息操作打磨（2026-10-09 追加）

首轮验收截图暴露的问题：连接线是列表级的一根伪元素，穿过审批行背景并在末尾留下残段；状态点用 9px 实心圆加边框拼勾，与 AppIcon 风格不符；灌溉建议仍待确认却显示为已完成，汇总写成“已完成 2 项操作”；后端摘要出现 `45.266%`、`80.00%` 和 `。；` 这类精度与标点瑕疵。

### 活动时间线

- 每行使用“图标列 20px + 内容列”的网格；连接线由每行自身绘制，从本行图标下沿连到下一行图标上沿，最后一行不绘制，任何行背景都不会被穿透。
- 状态图标统一为 16px、1.5 描边的内联 SVG，与 AppIcon 同一套线条语言：等待为空心圆，运行为旋转弧线（reduced motion 下静止），完成为细线勾圆，出错为感叹号圆，待确认为强调色空心圆。
- 标签 13px/500，说明 12px，行距一致；每行完成后在右侧显示等宽数字耗时。
- 折叠头使用 chevron 与语义摘要，例如“读取 1 项资料 · 1 项待你确认 · 用时 1.8s”，不再使用装饰圆点。
- 审批在时间线内只保留“生成灌溉建议 · 待确认”一行；时间线下方渲染独立操作卡片，展示地块、原因、时长与“去确认”。
- 后端摘要统一格式化：百分比保留 1 位小数，句末标点在拼接时去重。

### 时间标签

- 运行中：状态行显示实时计时“已用 12s”，等宽数字防抖。
- 完成后：消息底部常驻结束时间；当天显示 `HH:mm`，昨天显示“昨天 HH:mm”，更早显示“n 天前”；悬停或聚焦显示完整时间，使用 `<time datetime>`。时间来自后端持久化的 `created_at`。

### 消息操作栏

- 助手消息底部常驻：复制、从此处分支、朗读；用户消息常驻复制与时间。
- 复制：复制正文纯文本，成功后图标短暂变为勾并通过 polite 区域播报“已复制”。
- 分支：`POST /api/ai/conversations/{id}/branch`，请求体 `messageId`；在同一租户、同一账号、同一农场内创建新对话，复制截至该消息（含）的消息与活动摘要，标题加“（分支）”；跨租户或他人对话返回 404。
- 朗读：使用浏览器 `speechSynthesis` 以 `zh-CN` 朗读，再次点击停止；不支持时隐藏按钮。
- 图标 16px、1.5 描边、低对比灰，悬停提亮；点击区域不小于 32px；移动端常驻可见；每个按钮都有中文 `aria-label` 与 tooltip。
