# 数据链路与统计口径说明

本项目只使用虚构演示数据。本说明用于操作核对和比赛演示，不把模拟读数、AI 建议或采收台账当作真实农业效果证明。

## 数据从哪里来

| 数据 | 进入系统 | 保存与关联 | 使用位置 |
| --- | --- | --- | --- |
| 监测读数 | 模拟采集、人工录入、设备上报；兼容旧观测入口 | 新采集保存在 `telemetry_readings`，旧入口保存在 `observations`；统一读取，不重复写两份 | 设备、监测、运行概览、农情分析、决策证据 |
| 种植计划 | 农场内地块的种植计划 | 地块、作物、面积、起止日期、状态 | 有效在种计划、AI 作物背景、采收关联 |
| 农事任务 | 人工派工、现场问题转任务、人工批准 AI 巡查建议 | 任务与执行回执、日志 | 待办、完成率、问题闭环、决策复核 |
| 生产记录 | 收获登记 | 一条生产主记录；跟踪信息和旧关联表只是关系，不是额外产量 | 生产台账、汇总、趋势、AI 产量分析 |
| 告警 | 阈值与设备接收检查 | 未关闭状态包括待处理和已知晓；关闭后不再计入 | 预警、首页、工作台、AI 证据 |
| 日报 | 当天首次访问或定时生成 | 每农场每天一份冻结事实；模型可补充解释 | 首页简报、运行概览、展示大屏 |

租户来自登录身份。业务查询和关联必须同时满足租户、农场或地块范围；平台账号不能读取经营数据。有业务历史的地块不能直接搬到另一农场，以免历史产量、任务、问题和决策随之漂移。

## 产量与任务口径

| 位置 | 时间范围与计数规则 |
| --- | --- |
| 全局经营汇总、农情累计产量 | 截至农场今日的有效生产记录；排除作废及未来日期记录 |
| 工作台产量趋势、地块产量 | 所选天数，含农场今日；以页面显示的起止日期为准 |
| 运行概览采收流水线 | 近 30 个自然日，含今日；不随监测的 24 小时 / 7 天 / 30 天按钮改变 |
| AI 产量同比较 | 两个完整的 30 天区间，排除尚未结束的今日；同时显示两个区间日期 |
| 日报产量 | 生成时近 7 个自然日，含报告当天；生成后不被后续补录覆盖 |
| 任务完成率 | 已完成数 ÷ 非取消任务数；取消任务单列，不能拉低完成率；无可计任务显示暂无数据 |
| 待办与逾期 | 待处理或进行中；早于农场今日截止的未结束任务为逾期 |

产量单位是 kg，面积是亩。没有生产记录表示“没有记录”，不表示实际产量为 0。图表缺测显示空缺，实际采集到的 0 仍显示为 0。所有业务日期按 `farm.zone`（默认 `Asia/Shanghai`），不跟随服务器时区改变。

生产记录以 `production_tracking` 存在时的整行关联为准；没有该行才兼容 `production_lineage`。更正时明确清空的关联不能被旧关系重新补回。作废保留原始记录和更正历史，但退出经营统计。相同请求重试返回原记录。

## 监测读数如何判定

- 当前值按观测时刻、接收时刻和记录标识确定；完全相同的跨存储记录优先使用新采集表。历史图按设备、指标、观测时刻保留最后更正值，避免同一采样重复加权。
- 只使用设备已配置的指标。来源须与接入配置一致，设备须处于在用状态，值须在指标允许范围，观测时刻不能晚于当前时刻。
- 通用有效期为 `max(180 秒, 采集间隔 × 3)`，严格小于有效期才算新鲜；不同指标分别判断，不能用一个正常通道替代另一个缺测通道。
- 人工测量明确标为人工。运行概览“此刻设备指标可用率”含人工测量，表示在用设备至少一个配置指标当前有效；“正常接收设备”反映自动设备的接收情况，两者含义不同。
- 灌溉控制还有更严格的 15 分钟墒情门槛，并需通过设备反馈与人工确认。显示有效不等于可以直接控制。
- 旧观测缺少真实接收时刻时保留未知，不用观测时刻冒充接收时刻；新写入会保存真实接收时刻。历史未知接收时刻仅作为确定排序的回退条件，不能据此声称可靠识别旧记录的接收先后。

旧 H2 观测没有保存原服务器时区，迁库或更换服务器时区前需核实原环境；不能仅凭旧日期字段猜测后批量转换。MySQL 旧观测保持既有 UTC 存储格式，读取时统一转换后再与新采集时间比较。

原始历史保留供核查。异常来源、未来时间或不合格值不能因“过滤掉较新更正后回退旧值”而恢复成有效证据。

农场与 AI 历史汇总在选定最后更正后排除物理范围异常和非整数的离散量；设备诊断图保留这类异常原值，并注明诊断用途，便于追溯。土壤水分趋势按有效采样记录计算均值，不按地块面积加权，也不代表整块田的真实含水率。

## 页面上的重复与差异

同一数据在经营总览、任务明细、AI 证据中出现，分别用于概览、操作与解释，不代表数据库重复。首页日报摘要已去除与实时经营卡重复的生产、任务数字，保留优先行动与生成时刻；展开后仍可查看冻结证据。

日报始终是快照。生成后，若种植、待办、逾期、生产、现场问题或在用设备计数变化，会提示业务数据已更新。这项提示只比较业务计数，不保证监测读数没有变化，也不代表快照与当前所有明细完全相同；实时状态以任务、生产与监测页面为准。

告警总数、任务总数按全量符合条件的记录计算。列表达到显示上限时明确提示截断，不能以列表长度当作总数。告警已知晓不等于已解决。

## 使用“数据核对”

管理员进入 **运行概览 → 页面底部“数据核对” → 开始核对 / 重新核对**。核对是只读操作，不调用模型，不修改原记录。

当前 10 项规则检查：未来生产日期、生产与种植/采收任务关联、疑似重复生产组、无种植关联的兼容记录、未结束种植时间重叠、种植面积、任务完成回执、现场问题与任务关系、设备与地块农场归属、决策与地块农场归属。

错误需定位记录并人工更正；疑似重复需核实是否分批采收，再决定是否作废；兼容旧记录缺少关联只作为信息，不直接判错。每项显示全量命中数，最多 20 个样本。汇总是规则命中次数，同一记录可能命中多项，不能解读为去重后的错误记录数。

核对规则不能发现所有可能的业务错误，例如合理范围内却填写错误的称重数值，仍需与现场记录核对。不要为了让报告归零而自动删除或补造数据。

管理员也可导出本地核对结果，在项目根目录的 PowerShell 执行（口令文件使用你自己的本地文件）：

```powershell
$env:FARM_AUDIT_BASE_URL = 'http://127.0.0.1:9175'
$env:FARM_AUDIT_TENANT = 'demo-a'
$env:FARM_AUDIT_USERNAME = 'admin'
$env:FARM_AUDIT_PASSWORD_FILE = '你的本地口令文件绝对路径'
node tools/audit_data_chain.cjs
Remove-Item Env:FARM_AUDIT_PASSWORD_FILE
```

工具读取当前租户的未归档农场，结果保存在被 Git 忽略的 `.cache/data-audits/`，包含核对样本标识，不保存登录口令或令牌；自建临时会话在结束时注销。必须运行包含数据核对接口的新版后端。历史归档农场可通过管理员的指定农场接口单独核查。

## 开发验证

运行 `scripts/verify.ps1` 完成后端、前端、构建、字体及项目检查；已准备本机独立 MySQL 环境时，再运行 `scripts/verify-mysql.ps1`。跨接口测试使用已知虚构账本，对比累计、窗口、趋势、地块、AI 与日报的手算预期，覆盖未来记录、作废、关联双表、截断计数、隔离与并发更正；采集链测试覆盖旧入口、同刻更正、来源、时间、精度与控制门槛。

不要使用经营库运行自动化测试，不把测试夹具或隔离演示环境的通过结果等同于现有数据库已经核查无误。
