# 田间实景与摄像头

入口为左侧“农场与设备 → 田间实景”。顶部“当前农场”决定画面范围，机位列表只显示该农场的摄像头。选择机位后可查看大图或视频、重新加载、全屏查看；画面上保留农场、地块与来源标记。设备采样时间是状态上报时间，不是图片拍摄时间。

## 演示画面

五个农场各配置至少三台 `CAMERA` 视频监测设备，初始共十五个机位，关联各自农场的不同地块与安装位置。保留已有机位，再按田块长势、灌溉渠道、场区道路等用途补齐。每场预置三幅不同画面，跨农场复用已有五张素材；各机位可独立修改媒体地址，不共享设备记录。

预置图片和初始设备状态用于功能演示。演示说明集中在播放器区域，保留“演示画面 · 非实时”标记及简短说明，不叠加拍摄时间；机位名称、数量统计和列表不再重复来源说明。设备上报状态每 30 秒刷新，静态图保持不变；“重新加载”仅重新加载媒体。图片来源与生成记录仍完整保留。

资源保存在 `frontend/public/camera-demo/`，五张 PNG 可随项目离线部署。完整生成提示词与来源说明保存在该目录的 `provenance.json`。没有使用第三方农场摄像头或其账号。

## 在设备台账维护

1. 在田间实景点击“管理这台摄像头”，直接进入设备台账，筛选本农场的视频监测设备并打开对应详情；台账中的“查看画面”可返回该机位。农场地图原有摄像头的设备详情也可预览画面。
2. 管理员可新增或编辑“视频监测”设备，设置所属农场、关联地块、名称、型号与安装点位。已有设备不可直接跨农场迁移，保留其历史归属。
3. 在“田间画面配置”填写机位说明，选择画面来源：暂不配置、预置图片、HTTPS 图片源或 HTTPS 视频源。新增摄像头自动采用 `CAMERA_ONLINE` 状态指标；已有指标保留历史。
4. 保存后立即在详情中预览。维护中或停用的摄像头显示明确提示，不继续加载媒体。查看者和操作员可以查看，只有管理员可以维护设备与画面配置。

画面来源与设备的模拟/人工/HTTP 上报方式是两个不同配置。图片能打开不等于摄像头在线；设备有在线反馈也不保证视频地址可播放。失败时显示具体提示并提供重新加载，不自动切换到别的农场图片。

## 接入实际画面

可填写不包含账号口令的 HTTPS 图片地址，或浏览器支持的视频地址（例如 MP4 / WebM）。播放组件使用原生视频控件，支持播放、暂停、音量和进度操作。图片和录像不会被标为实时直播。地址作为私有业务配置保存到当前数据库，不写进项目源码。

原始 RTSP、GB28181、云台控制、录像检索、NVR 与直播网关尚未接入。需要现场媒体网关输出浏览器支持且已授权的播放地址；鉴权、有效期、跨域策略及实际直播能力由媒体服务提供。目前浏览器直接加载配置的 HTTPS 媒体，后端不代抓远程地址，也不把平台登录令牌传给媒体服务。图片缓存行为由媒体服务响应头决定。

## 接口与数据

- `GET /api/farms/{farmId}/cameras`：返回该农场名称及摄像头列表。租户来自认证会话，跨租户农场返回 404，平台账号返回 403。
- `GET /api/assets`、`GET /api/assets/{id}`：摄像头额外返回 `camera` 对象，包括 `mode`、`demoScene`、`sourceUrl`、`viewLabel`、`playbackUrl`。
- 原 `POST /api/assets`、`PUT /api/assets/{id}` 增加可选 `camera` 对象，与设备资料同一事务保存，沿用 `revision` 并发校验。旧客户端省略 `camera` 时保留原配置；选择 `NONE` 清空媒体地址。改为其他设备类型会移除摄像头配置。
- `GET /api/assets/catalog` 增加 `cameraScenes` 演示场景选项。
- 新增 `camera_profiles` 表，以 `(tenant_id, device_id)` 为主键，H2 和 MySQL 建表文件同步维护。

本次升级只为 `demo-a` 已知五座未归档农场补齐至三台摄像头，使用 `cam2<farmId>` 标记防止重复添加。已有视频地址、自定义机位名称、点位及停用状态均保留；仅替换旧版默认名称与说明。其他租户、普通新建农场与归档农场不自动添加设备。升级完成后的人工增删由台账管理，重启不会强制恢复已删除机位。新增点位按已有地块边缘布置，属于场景配置而非实测位置。

验证：运行 `scripts/verify.ps1`；浏览器验收运行 `node tools/test_field_cameras.cjs`（先构建前后端）。浏览器脚本使用临时端口与内存数据库，验证五农场画面区分、切换农场、台账编辑、状态与错误反馈，以及移动端和深色主题，不改动本地运行数据库。
